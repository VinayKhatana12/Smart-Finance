# Smart Finance — Database Schema (PostgreSQL + Drizzle ORM)

The database is **PostgreSQL 14+** (developed against 18). Access goes through Drizzle ORM (`server/src/db/schema.ts`); migrations are plain SQL files in `server/drizzle/` generated by drizzle-kit.

Design rules:

- **Money is integer minor units** (`amount_minor`, cents/paise) — `integer` columns, `CHECK >= 1`. No floating-point money anywhere.
- **Primary keys are UUIDs** (`gen_random_uuid()`), so ids are non-enumerable.
- **Timestamps are `timestamptz`**; every table carries `created_at` / `updated_at`.
- Enumerations are real Postgres enums: `currency`, `transaction_type`, `goal_hue`, `goal_status`.
- Referential integrity is enforced: every resource row references `users(id) ON DELETE CASCADE`.
- `budgets.spent` is **never stored** — spent amounts are computed from `transactions` at query time (phase 3).

## users

| Column | Type | Rules |
| --- | --- | --- |
| id | uuid PK | `gen_random_uuid()` |
| name | text | 2–80 chars (validated in Zod + app layer) |
| email | text | unique index `users_email_unique`, lowercased by the app |
| password_hash | text | bcrypt (12 rounds); never selected into API responses |
| currency | currency enum | default `'USD'` |
| created_at / updated_at | timestamptz | defaults |

## transactions

| Column | Type | Rules |
| --- | --- | --- |
| id | uuid PK | |
| user_id | uuid FK → users | `ON DELETE CASCADE` |
| type | transaction_type enum | `income` / `expense` |
| amount_minor | integer | `CHECK (amount_minor >= 1)` |
| category | text | lowercase slug (`groceries`, `salary`, …) |
| description | text | ≤ 140 chars, default `''` |
| spent_at | timestamptz | when the money moved (defaults to now) |
| created_at / updated_at | timestamptz | |

Indexes: `(user_id, spent_at DESC)` for lists, `(user_id, type, category)` for category reports.

## budgets

One budget per user per category per month.

| Column | Type | Rules |
| --- | --- | --- |
| id | uuid PK | |
| user_id | uuid FK → users | cascade |
| category | text | |
| month | text | `CHECK (month ~ '^\d{4}-(0[1-9]|1[0-2])$')` — `YYYY-MM` |
| limit_minor | integer | `CHECK (limit_minor >= 1)` |
| created_at / updated_at | timestamptz | |

Indexes: unique `(user_id, category, month)`.

## goals

| Column | Type | Rules |
| --- | --- | --- |
| id | uuid PK | |
| user_id | uuid FK → users | cascade |
| name | text | ≤ 80 |
| target_minor | integer | `CHECK (target_minor >= 1)` |
| saved_minor | integer | default 0, `CHECK (saved_minor >= 0)` |
| deadline | date | nullable |
| hue | goal_hue enum | pot tint (`blue amber teal rose violet green`) |
| status | goal_status enum | `active` / `achieved` / `archived` |
| created_at / updated_at | timestamptz | |

Indexes: `(user_id, status)`.

## Migrations

```bash
cd server
npm run db:generate   # edit src/db/schema.ts first; writes SQL into server/drizzle/
npm run db:migrate    # applies pending migrations to DATABASE_URL
```

Migrations are committed SQL files — the server never mutates the schema on boot.

## Seed vs. real data

- Demo/seed data will live **only** in `server/src/scripts/seed.ts` (phase 2), writing to a **separate demo user** (`demo@smartfinance.local`).
- Seed scripts are never run automatically on server start; they are explicit commands.
- Dashboards only ever render the requesting user's own rows — no hardcoded financial data in the client.
